# Цены: приём от поставщика (push) и отдача каталогу (pull)

Две точки входа, обе в папке `/api/` в **корне сайта DLE** (рядом с `engine/`, `index.php`):

| URL | Кто дёргает | Метод | Авторизация |
|---|---|---|---|
| `/api/prices-push.php` | база | `POST` | заголовок `X-Api-Token` |
| `/api/prices.php` | каталог на сайте | `GET` / `POST` | нет (публичный, только по конкретным артикулам) |

Код совместим с **PHP 5.6** (на ней сейчас работает gqgroup.kz) и с PHP 7/8 — при обновлении
версии править ничего не нужно.

Данные лежат в таблице `dle_prices`. Пишем через `INSERT ... ON DUPLICATE KEY UPDATE`,
никаких `TRUNCATE`: обрезанная или битая выгрузка не сносит прайс.

## 1. Установка

```bash
# 1. таблица
mysql -u USER -p BASE < api/schema.sql     # префикс dle_ поправить, если у сайта другой PREFIX

# 2. файлы — в корень сайта
#    /api/prices.php, /api/prices-push.php, /api/_bootstrap.php,
#    /api/.htaccess, /api/.user.ini, /api/schema.sql
#    и папка /api/logs/ с правами на запись (chmod 775)

# 3. токен
openssl rand -hex 32                        # сгенерировать
cp api/config.sample.php api/config.php     # вписать в 'token'
chmod 640 api/config.php
```

`config.php` 
Альтернатива файлу: переменная окружения `GQ_PRICES_TOKEN`.

Проверка после заливки:

```bash
curl -i https://gqgroup.kz/api/_bootstrap.php      # ждём 403 — служебные файлы закрыты
curl -i https://gqgroup.kz/api/prices.php          # ждём 400 {"error":"no sku given"} — эндпоинт жив
```

## 2. Протокол для поставщика

```
POST https://gqgroup.kz/api/prices-push.php
X-Api-Token: <секрет>
Content-Type: application/json; charset=utf-8
Content-Encoding: gzip        (необязательно, но для полной выгрузки желательно)

[
  {"sku": "A9F74206", "name": "Автомат iC60N 1P 6А", "price": 12345.67, "currency": "KZT", "active": true},
  {"sku": "NE2010",   "name": "Шина заземления",     "price": 34211.50}
]
```

Поля: обязателен только `sku` (синонимы `artikul`, `article`) и `price`.
`name` — до 255 символов, `currency` — по умолчанию `KZT`, `active` — по умолчанию `true`
(снятая с продажи позиция: `"active": false`, строка остаётся в базе).
Цена принимается и числом, и строкой в формате — `"34 211,50"`.

### Формат для больших выгрузок — NDJSON

Обычный JSON-массив приходится держать в памяти целиком: на PHP 5.6 это ~80 МБ на 50 000 позиций,
а на 100 000+ выгрузка упрётся в `memory_limit`. Поэтому полный прайс лучше слать **NDJSON** —
по одному объекту в строке:

```
POST https://gqgroup.kz/api/prices-push.php?full=1
X-Api-Token: <секрет>
Content-Type: application/x-ndjson
Content-Encoding: gzip

{"sku":"A9F74206","name":"Автомат iC60N 1P 6А","price":12345.67}
{"sku":"NE2010","name":"Шина заземления","price":34211.50}
```

Приёмник читает такое тело построчно и пишет пачками — расход памяти не зависит от размера файла
(50 000 позиций: 10 МБ памяти вместо 80 МБ, ~4 с). Поля те же, флаг полной выгрузки передаётся
в адресе: `?full=1`. Битая строка не ломает весь файл — она попадает в `skipped` / `errors`.

Полная выгрузка в обычном JSON — конверт с флагом:

```json
{"full": true, "items": [ ... ]}
```

При `full: true` всё, чего нет в пачке, помечается `active = 0` (не удаляется).
Страховка: если в пачке меньше `min_full_items` (по умолчанию 100) валидных строк,
деактивация не выполняется — обрезанный файл не обнулит каталог. В ответе видно,
сработало ли: поле `full`.

Ответ — всегда JSON и осмысленный HTTP-код, по нему поставщик понимает, дошло или нет:

```json
{"ok":true,"received":50000,"upserted":50000,"skipped":0,"deactivated":3,"full":true,"errors":[]}
```

| Код | Когда | Что делать поставщику |
|---|---|---|
| 200 | принято | смотреть `skipped` / `errors` (первые 20 проблемных строк) |
| 400 | битый JSON или нет валидных позиций | не повторять, чинить выгрузку |
| 401 | нет/неверный токен | не повторять |
| 405 | не POST | — |
| 413 | тело больше лимита | слать частями или с gzip |
| 500 | ошибка на нашей стороне | повторить через минуту |

Пример отправки:

```bash
curl -sS -X POST "https://gqgroup.kz/api/prices-push.php?full=1" \
  -H "X-Api-Token: $TOKEN" \
  -H "Content-Type: application/x-ndjson" \
  -H "Content-Encoding: gzip" \
  --data-binary @prices.ndjson.gz
```

## 3. Отдача цен каталогу

```
GET  /api/prices.php?sku=A9F74206,NE2010,412431
POST /api/prices.php     {"skus":["A9F74206","NE2010"]}
```

```json
{
  "ok": true,
  "count": 2,
  "items": {
    "A9F74206": {"price": 13999, "currency": "KZT", "name": "Автомат iC60N 1P 6А",
                 "active": true, "updated": "2026-08-18 10:18:54"},
    "NE2010":   {"price": 35000, "currency": "KZT", "name": "Шина заземления",
                 "active": true, "updated": "2026-08-18 10:18:54"}
  },
  "missing": ["412431"]
}
```

* Артикулы сравниваются без учёта регистра; ключи в ответе — ровно в том написании, в каком пришли в запросе.
* За раз не больше `max_query` артикулов (по умолчанию 500), иначе 413. Клиент бьёт список на пачки.
* Ответ кэшируется браузером на `cache_ttl` секунд (по умолчанию 300).
* Выгрузить весь прайс одним запросом нельзя — только по конкретным артикулам.
* Ответ кэшируется браузером по URL: после свежей выгрузки страница может до `cache_ttl` секунд
  показывать прошлую цену. Если это мешает (например, при проверке после заливки) — поставить
  `'cache_ttl' => 0` в `config.php`, тогда ответ идёт с `Cache-Control: no-store`.
* Заголовков CORS нет намеренно: эндпоинт рассчитан на запросы с самого gqgroup.kz.

Клиентская часть — `prices-client.js`: положить в `templates/2020/js/` и подключить в `brand.tpl`
перед `</body>`:

```html
<script src="{THEME}/js/prices-client.js" defer></script>
```

Скрипт сам находит таблицу серии, спрашивает цены пачками по 200 и обновляет только изменившиеся
ячейки; обновлённой ячейке добавляется класс `price-fresh` — при желании его можно подсветить в CSS.
Позиции с `active: false` и те, которых нет в прайсе, не трогаются вовсе. Если эндпоинт недоступен — на странице остаются цены из `data/<бренд>.js`, ничего не ломается.

## 4. Что согласовать 

1. Формат JSON — как выше (`sku`, `name`, `price`, `currency`, `active`).
2. Токен `X-Api-Token` — передать отдельным каналом, не в чате.
3. Полная выгрузка (`full: true`) или только изменившиеся позиции.
4. Расписание: раз в сутки ночью / при каждом изменении цены.
5. Снятые с продажи позиции — `active: false` (или полная выгрузка, тогда они деактивируются сами).
6. Только HTTPS — иначе токен уйдёт открытым текстом.
7. С какого IP шлёт — если фиксированный, впишем в `allow_ip` и закроем эндпоинт ещё и по IP.

## 5. Что уже сделано для надёжности

* Подготовленные запросы вместо конкатенации SQL — инъекции невозможны.
* Реквизиты базы читаются из `engine/data/dbconfig.php` **как текст** (только строки `define`),
  сам файл не выполняется: в этой сборке DLE он в конце создаёт `new db(...)`, и обычный
  `include` из стороннего скрипта на нём падает.
* Драйвер выбирается сам: `mysqli`, а если его на сервере нет — `PDO`. Обе ветки протестированы.
* Транзакция + `rollback` при ошибке: либо приезжает вся пачка, либо ничего.
* Запись пачками по 500 строк одним `INSERT`, буфер сбрасывается по ходу разбора.
  Проверено на PHP 5.6: 50 000 позиций — 4–7 с, пик памяти 10 МБ (NDJSON) / 80 МБ (JSON-массив).
* `hash_equals` для токена (защита от подбора по времени ответа), поддержка `Authorization: Bearer`.
* Валидация каждой строки: длина артикула, числовая цена, обрезка имени, whitelist валюты.
  Кривые строки пропускаются и попадают в `errors`, остальные записываются.
* Лимит тела запроса, поддержка gzip, лимит числа артикулов в запросе цен.
* Никаких HTML-ошибок наружу: любой fatal/exception отдаётся как JSON 500, детали — в `api/logs/`.
* `.htaccess` закрывает всё, кроме двух эндпоинтов (бутстрап, конфиг с токеном, схема, логи).
* Работает и без расширения `mbstring`, и без `mysqlnd` (есть запасные реализации) —
  обе ветки проверены на PHP 5.6.

## 6. Ограничения, о которых стоит помнить

* Публичный `prices.php` не имеет своего рейт-лимита — при необходимости прикрутить на уровне
  Apache/nginx (mod_evasive, limit_req) или fail2ban по логам.
* PHP 5.6 снята с поддержки в 2018 году — обновление сайта до 7.4+ желательно само по себе,
  эндпоинты к этому готовы. До обновления полную выгрузку слать в NDJSON.
* `post_max_size`/`memory_limit` заданы в `.user.ini` и `.htaccess`. Если хостинг их игнорирует,
  выгрузку больше ~8 МБ придётся слать частями или с `Content-Encoding: gzip`.
* Соответствие «артикул из прайса ↔ артикул в `data/<бренд>.js`» нигде не проверяется:
  что не совпало — окажется в `missing`. Разовый скрипт сверки стоит сделать после первой выгрузки.
